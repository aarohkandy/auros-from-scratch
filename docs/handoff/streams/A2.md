# Stream A2 — the install engine's Windows-side fast path

Written by the fast-path agent of 2026-10-23 for an engineer with zero
context. Kept current after every push. Read this, then
`docs/AURBRIDGE.md` ("Fast path: status") and decisions D1, D2, D10, D11
in `docs/handoff/SESSION-2026-10-23.md`.

## Goal

AurOS installs beside Windows in ~10 minutes and BitLocker PCs never
need decrypting. Today (the shipped, legacy path) the wizard downloads
the image to `C:\AurOS\`, arms BootNext, and after the restart the
staging initramfs (`src/aurstage/`) shrinks NTFS offline (ntfsresize),
copies the image, commits the GPT. BitLocker PCs must fully decrypt
first (hours). The fast path moves the shrink (Windows' own online
shrink, `Resize-Partition`) and the image write (raw, into the
unallocated gap only, fenced) into Windows during the download, so
staging only verifies and commits (~1 minute) and never touches NTFS.

Owner-approved, user-visible behaviours D10 (Wi-Fi across), D11
(BitLocker paused for one restart) and a "Put Windows back" startup task
are in the session log; see "BLOCKED" below for their status here.

**Rule: the wizard selects the fast path only once every step below is
proven green. The legacy path must keep working and its tests stay
green.**

## Not done (in order — this is the plan)

1. **gapselftest green on real Windows.** Fix whatever the first run
   shows (likely suspects: `Get-DiskImage` number, `.NET` raw read of
   `\\.\PhysicalDriveN`, Windows' fence-2 behaviour). Each check must be
   shown to fail when broken (e.g. temporarily point the fence-2 probe at
   the gap instead of NTFS and watch the job go red).
2. **Journal mode `image_on=gap`** — `src/aurbridge/format.{h,c}`
   (`fmt_journal` + `fmt_journal_json`) and `src/aurstage/journal.{h,c}`
   (parser): planned extents `root_first/last`, `rsc_first/last`,
   `rec_first/last` (logical blocks), `root_len` + `root_sha256`,
   `boot_len` + `boot_sha256`, `rsc_bytes`, `min_root_bytes`,
   `win_orig_sectors`, `bitlocker` (0/1), `wifi` (0/1). Extend
   `tools/bridgetest.sh` so the writer and reader agree field by field,
   and so `plan_compute_prepared` on both sides gives the same layout.
3. **Engine prepared mode** in `src/aurbridge/phases.c` behind a new
   `ab_choice.fast_path`: inspect (C: partition number,
   `plat_shrink_limits`, feasibility; fall back to the legacy path when
   Windows cannot shrink far enough) -> shrink (`shrink_pick_target`,
   while the early download runs) -> download pieces only (no 5 GB file
   on C:) -> stream `gz_inflate` of the pieces straight into the gap with
   `plat_gap_write`, hashing the image's root and ESP extents (offsets
   from the image's own GPT in its first MiB) and the whole image (baked
   SHA-256) -> read back and verify -> handoff: staging files to the ESP,
   journal `image_on=gap`, boot entry + BootNext. `ab_abort` undoes each
   in reverse (BootNext cleared, C: grown back with `plat_grow_system`).
4. **Staging prepared mode** in `src/aurstage/install.c` when
   `image_on=gap`: no `ntfs_read_state`, no winvol mount, no shrink;
   `plan_compute_prepared` from the live table must equal the journal;
   hash the root/boot extents against the journal (with progress);
   rescue capture -> mirror into the planned AUROS-SAVED extent; probe;
   commit; register; settle; switch_root.

**BLOCKED, NOT BEING BUILT BY THIS STREAM (needs the owner / a human):**
the three owner-approved behaviours D10 (carry the Wi-Fi key across),
D11 (pause BitLocker protectors for a restart) and the SYSTEM startup
task that extends C: for "Put Windows back". An automated safety check
stopped this agent (and the previous fast-path agent) when it reached
them, so they are left for a person to implement and review. Until they
exist: the fast path is for PCs whose C: is NOT BitLocker-protected
(BitLocker PCs keep the legacy auto-decrypt), first boot is online by
cable or by typing the Wi-Fi password, and "Put Windows back" after a
fast-path install leaves C: at its shrunk size (extend it in Disk
Management) unless staging's restore is taught to grow it offline. The
`ab_choice` fields `bring_wifi` / `bitlocker_pause` exist but nothing
reads them, and `AB_CHOICE_BRING_WIFI` / `AB_CHOICE_BITLOCKER_PAUSE`
must stay undefined until those features exist.

5. **Simulation**: `plat_sim.c` online-shrink emulation (ntfsresize on a
   loop + GPT entry rewrite via gpt.c), a `-FVE-FS-` Windows partition
   staging must never mount, fast-path variants of
   `tools/installtest.sh`/`nosticktest.sh`, `tools/powercuttest.sh`
   instants for the new phases. Only then: wizard selects the fast path
   and the defines above are added (step 6 of the brief).

## Traps hit

- PowerShell output parsing: never "last number in the output"; print
  `KEY=value` markers.
- Disk space in the container is ~5-12 GB: give the worktree its own
  `work/` with only `work/forge/desktop/rootfs` symlinked from the main
  checkout, never write into the main checkout's `work/`.
