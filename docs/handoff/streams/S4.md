# Stream S4 — theft protection (encrypted disk + PIN, owner decision D9)

For a zero-context engineer. Read this, then `docs/security/THEFT.md`
(the design), then `docs/handoff/STREAMS.md` (common rules: branch
`claude/brave-hypatia-x72g1m` only, own worktree, push often, plain
words, prove each check fails when broken).

## Goal

AurOS's root partition is LUKS2, unlocked by TPM 2.0 (PCR 7) + a 4-6
digit PIN typed on a friendly full-screen page at start, the same PIN
on wake (aurshell lock screen via PAM), an honest no-TPM fallback, a
rescue code she can keep, Adiantum without AES-NI, re-sealing around
PCR 7 changes. Proven in a KVM VM with swtpm on GitHub Actions.

## Traps

- Noble's systemd 255 ships `systemd-cryptsetup` and the
  `libcryptsetup-token-systemd-tpm2.so` plugin inside the `systemd`
  package; the TPM libraries (`libtss2-*`) are only dlopened, so
  initramfs hooks must copy them by hand (copy_exec does not see them).
- `cryptsetup` the CLI is in `cryptsetup-bin` (not installed in the
  image by default). Do NOT install `cryptsetup-initramfs`: its
  console prompt would replace ours.
- PCR 7 alone does not stop a signed Ubuntu live stick; the PIN is what
  protects (THEFT.md section 3). Never enrol TPM-only.
- grub cannot read the LUKS2 root: boot files must be on AUROS-BOOT
  before the root is encrypted, or the PC will not start.
- The container has no KVM and no device-mapper: keyslot work can be
  tested locally on a LUKS2 image *file* with swtpm
  (`SYSTEMD_TPM2_DEVICE=swtpm:path=...`), activation only on Actions.

## How to verify

- Locally: `sh tools/theftunit.sh` (once it exists) -- keyslot, PIN,
  wrong-PIN, rescue-code logic against swtpm and a LUKS2 file.
- On Actions: the `theft` workflow (push touching its paths or
  `[theft]` in the subject); evidence as prerelease `theft-<run_id>`
  (`releases/download/theft-<run_id>/theft-evidence.txt`).
