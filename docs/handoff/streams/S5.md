# Stream S5 — AurOS's own update channel

Written for an engineer with zero context. Updated after each step.
Full design: `docs/security/UPDATES.md` (lands with the code).

## Goal

AurOS's own components (aurshell and the other desktop programs, aurfirst
and the first-boot scripts, the boot chain, Ferry, themes, our `/etc`
settings) had **no update path**: `build/forge` compiles them into the
image as loose files that dpkg does not know about, so a security fix
could never reach an installed computer. Ubuntu's own packages already
update daily (unattended-upgrades, `rootfs/etc/apt/apt.conf.d/20auto-upgrades`).

Owner's rules: no Microsoft service, no code-signing certificate. Our own
OpenPGP key for an apt repository is fine and necessary.

## Design (decided)

1. **Our files become dpkg packages.** New script `build/aptchannel`.
   A one-line hook in `build/forge` (`stage_squash`, before `seal_rootfs`)
   runs `build/aptchannel image "$RFS"`, which packs every AurOS file
   in the rootfs into `auros-desktop`, `auros-first`, `auros-bootchain`,
   `auros-ferry`, `auros-config` (our `/etc` overlay, as conffiles),
   `auros-archive-keyring`, plus the metapackage `auros` (exact-version
   Depends, so they move together), `dpkg -i`s them in the chroot (files
   are identical, dpkg just takes ownership), and keeps the `.deb`s in the
   image at `/var/lib/auros/debs/` (≈ 4 MB; also an offline repair copy).
   Version = `<os_version>.<commit time YYYYMMDDHHMMSS UTC>` — always rises.
   Rule: a file from `rootfs/`, `themes/`, `shells/` is packaged only if it
   is byte-identical to the repository's copy (so a profile that changed a
   file keeps it image-owned and no profile is overwritten by another's).
   `update-grub`/`grub-install` in `/usr/sbin` stay behind forge's
   dpkg-divert; `auros-bootchain`'s postinst refreshes those copies.
2. **Repository = a flat apt repo on a fixed GitHub prerelease tag `apt`**:
   `https://github.com/<owner>/<repo>/releases/download/apt/` (`InRelease`,
   `Release`, `Release.gpg`, `Packages(.gz)`, the `.deb`s). Never "latest"
   (it must not steal the website's `releases/latest`). Works without
   Pages. The URL is DERIVED (`GITHUB_REPOSITORY` on Actions, else the git
   remote, else `AUROS_APT_URL`); the tag name is the one constant
   `APT_TAG` in `build/aptchannel`.
3. **Signing**: ed25519 OpenPGP key, private half only in the repository
   secret `AUROS_APT_SIGNING_KEY`; public half committed at
   `rootfs/usr/share/keyrings/auros-archive-keyring.asc`. The image's
   `/etc/apt/sources.list.d/auros.sources` (written by the hook, only when
   that key file exists) pins `Signed-By:` to that file. No key committed →
   no source written (an image never points at a repo it can't verify).
4. **What the machine accepts**: `rootfs/etc/apt/preferences.d/auros`
   (our repo may supply only `auros*` packages; everything else from it is
   pin -1, so even a leaked key can't replace Ubuntu's libc) and
   `rootfs/etc/apt/apt.conf.d/53auros-updates` (unattended-upgrades origin
   `origin=AurOS,label=AurOS,archive=stable`). apt never downgrades.
5. **Publishing**: `.github/workflows/aptrepo.yml`. `[apt]` / `[apt TAG]` in
   the commit subject → download that tagged release's image pieces, take
   `/var/lib/auros/debs/` out of the image, refuse lower versions than
   published, build + sign the repo, verify with `gpgv` against the
   COMMITTED key, upload, read back through GitHub's redirect and verify
   again. Refuses if the secret's key is not the committed one.
6. **Test with a throwaway key** (`tools/updatetest.sh`, also run in
   aptrepo.yml in fresh `ubuntu:24.04` containers): a signed update installs
   by itself via the real unattended-upgrades; unsigned, wrong-key,
   tampered `.deb`, tampered `Packages`, downgrade and foreign-package
   (e.g. `gpgv` 99 from our repo) are refused; `--break=trusted|pin`
   proves those checks fail when the protection is removed.
7. **Key expiry 3 years; rotation** by shipping the next key inside
   `auros-archive-keyring` while the old one is valid, signing with both,
   then only the new (full steps in UPDATES.md).

## Owner's one-time step (also in docs/OWNER-SETUP.md §4)

Make the key on your own computer (Linux or Mac with GnuPG), paste the
private half into the secret `AUROS_APT_SIGNING_KEY`, keep an offline copy,
tell an agent the fingerprint. Exact commands: `docs/OWNER-SETUP.md` §4.
Until then everything is built and tested; only the real publish waits.

## Traps

- Session log conflicts on every push: it is append-only, resolve by keeping both sides.
- `/usr/lib/auros/bootchain-apt` runs after EVERY dpkg run via apt
  (`52auros-bootchain`); in a test chroot clear it (`#clear DPkg::Post-Invoke;`)
  and never mount the host's `/sys` (bootchain writes EFI variables).
- GITHUB_TOKEN-made releases/tags trigger no workflows; schedule/dispatch only
  run on the default branch — so `[apt]` in a commit subject is the trigger.
- Container disk is nearly full (≈2 GB): keep scratch tiny.

## How to verify

- `sudo sh tools/updatetest.sh live` (needs root, python3, gpg, dpkg-deb, apt).
- `sudo sh tools/updatetest.sh static work/forge/desktop/rootfs`.
- On a machine: `apt-cache policy auros`, `cat /etc/apt/sources.list.d/auros.sources`,
  `ls /var/lib/auros/debs`, `grep AurOS /var/log/unattended-upgrades/unattended-upgrades.log`.
