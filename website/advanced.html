For someone who knows computers

AurOS Setup stopped on this computer for a reason that someone comfortable with Windows’ settings can usually fix in under an hour. Setup has not changed anything. This page is for that person.

If that isn’t you, it is fine to stop here. Keep using Windows as it is. You can show this page to someone you trust who knows computers, or just leave it.

  • First, for either fix: copy the files, pause BitLocker
  • “This PC starts Windows the older way (BIOS)”
  • “AurOS can’t see this PC’s drive” (Intel RST or VMD)

First, for either fix

Both fixes are ordinary Windows and firmware changes, made with Windows’ and the computer maker’s own tools, not with AurOS. They are routine, but no change to how a computer starts is free of risk. So:

  1. Copy the files that matter (photos, documents, anything irreplaceable) to a memory stick or another drive. Check that the copies open.

  2. If BitLocker or “Device encryption” is on, find the recovery key, then pause it. Changing a firmware setting makes Windows ask for the 48-digit recovery key at the next start unless protection is paused. Control Panel → BitLocker Drive Encryption shows whether it is on, has Back up your recovery key, and has Suspend protection. Or, in a Command Prompt run as administrator:

    manage-bde -protectors -disable C: -RebootCount 3

    That pauses it for the next three starts, then it turns itself back on.

  3. Know how to open the firmware settings (the “BIOS setup”). Usually a key pressed straight after switching on: F2, Del, F10, F1 or Esc, depending on the maker; the logo screen often says which. On a PC that already starts the newer way there is also Windows’ own route: Settings → System → Recovery (on Windows 10: Update & Security → Recovery) → Advanced startup → Restart now, then Troubleshoot → Advanced options → UEFI Firmware Settings.

  4. Have the Windows account’s password to hand, not only its PIN. Safe Mode (used in the second fix) sometimes asks for the password.

The PC starts Windows the older way (BIOS)

Setup said: “This PC starts Windows the older way (BIOS)”The firmware is starting Windows in legacy BIOS mode (also called “Legacy” or “CSM”), from a disk with an MBR partition table.

Why AurOS needs the newer way (UEFI): the first time AurOS starts, it starts through a one-time start entry, so that if anything goes wrong the computer goes straight back to Windows by itself. BIOS mode has no such entry, so AurOS refuses rather than risk a computer that starts nothing.

Windows can be switched over without reinstalling it, using Microsoft’s own MBR2GPT tool (in Windows 10 version 1703 and later, and in Windows 11). Nearly every PC made since about 2012 can start the newer way.

Check first

  1. Press Start, type msinfo32, open System Information. BIOS Mode says Legacy. (If it already says UEFI, this section is not the reason; run Setup again.)

  2. Do the steps in First, for either fix.

The switch

  1. Press Start, type cmd, then choose Run as administrator.

  2. Check that the disk can be converted:

    mbr2gpt /validate /allowFullOS

    It must end with:

    MBR2GPT: Validation completed successfully

    If it says “Validation failed”, stop here

    Nothing has been changed. The usual cause is that the disk already has four partitions, and the tool needs room for one more (the new start-up partition). Don’t delete partitions to make it pass unless you know exactly what each one holds; a recovery partition put there by the maker is often one of them. Leave the computer on Windows.

  3. Convert it:

    mbr2gpt /convert /allowFullOS

    It ends with MBR2GPT: Conversion completed successfully and a reminder that the firmware now has to be switched to UEFI. Windows’ files are not touched; the tool rewrites the partition table and adds a small start-up partition.

  4. Restart and open the firmware settings. Change the start-up mode from Legacy (or CSM) to UEFI. Makers word it differently: Boot Mode: UEFI, Boot List Option: UEFI, CSM Support: Disabled, Launch CSM: Never. Secure Boot can be on or off; AurOS works either way. Save and exit (often F10).

  5. Windows starts as before. In msinfo32, BIOS Mode now says UEFI.

  6. Run AurOS Setup again from the Downloads folder.

If Windows does not start after the switch

Open the firmware settings again. Check that UEFI is chosen and that Windows Boot Manager is first in the start order. Don’t switch back to Legacy: the disk is now the newer kind, and Legacy mode cannot start it. If Windows still won’t start, Windows’ own recovery (from a Windows installation USB stick: Repair your computer → Startup Repair) is the next step.

Microsoft’s own description of the tool, with every condition it checks: MBR2GPT.EXE on learn.microsoft.com.

AurOS can’t see this PC’s drive (Intel RST or VMD)

Setup said: “AurOS can’t see this PC’s drive”The drive Windows is on is an NVMe drive behind Intel’s storage driver, in a mode that hides it from other systems: RAID On (Intel Rapid Storage Technology, “RST”), or Intel’s VMD controller on newer laptops.

Why AurOS needs it changed: in that mode, Linux, and so AurOS, cannot see the drive at all. One firmware setting presents the drive the standard way (“AHCI”, or plain NVMe). Windows works the same afterwards, with Microsoft’s standard driver instead of Intel’s. The setting does not change anything stored on the drive.

Check first

  1. Right-click Start, open Device Manager, open Storage controllers. It lists an Intel controller with RST, RAID, Premium or VMD in its name.

  2. Before changing anything, look for these two

    • Intel Optane memory acceleration. If the Intel Optane Memory and Storage Management program shows it switched on, switch it off there first and let it finish. Then carry on.
    • Two or more drives combined into one (a RAID 0, 1, 5 or 10 “volume”, shown in Intel’s program). If there is one, stop here. Switching the mode would make that combined drive unreadable. Leave this computer on Windows.

  3. Do the steps in First, for either fix, including the password.

The switch

Changing the setting alone would stop Windows starting (“INACCESSIBLE_BOOT_DEVICE”), because Windows would look for Intel’s driver. The safe way is to have Windows start once in Safe Mode, which picks up the standard driver by itself:

  1. Press Start, type cmd, then choose Run as administrator. Tell Windows to start in Safe Mode next time:

    bcdedit /set {current} safeboot minimal

    It answers The operation completed successfully.

  2. Restart and open the firmware settings. Find the storage setting and change it:

    • SATA Operation, SATA Mode or Storage Controller Mode: from RAID On (or Intel RST Premium) to AHCI; or
    • on newer laptops, VMD Controller or Enable VMD: switch it off.

    Some makers keep it under Advanced, Storage or System Configuration. Save and exit.

  3. Windows starts in Safe Mode (a black background with “Safe Mode” in the corners). Sign in, with the password if the PIN is refused. Open Command Prompt as administrator again and switch Safe Mode off:

    bcdedit /deletevalue {current} safeboot

    Then restart.

  4. Windows starts normally. In Device Manager, Storage controllers now shows Standard NVM Express Controller or Standard SATA AHCI Controller.

  5. Run AurOS Setup again from the Downloads folder.

If Windows does not start, or keeps restarting, after the change

Open the firmware settings and put the storage setting back as it was (RAID On, or VMD on). Windows starts again with Intel’s driver; nothing on the drive was changed. If it starts in Safe Mode, run bcdedit /deletevalue {current} safeboot and restart. Then leave the computer on Windows.

Anything else

If Setup stopped for a different reason, its own page says what can be done. Most of the other reasons (a drive that is failing, a Windows on an ARM chip, full-disk encryption from another company) are ones AurOS deliberately won’t work around, because getting them wrong could cost the files on the computer.

To ask a question, or to tell us Setup stopped when it shouldn’t have, open an issue on the AurOS project page. Please don’t include passwords, recovery keys or anything else private.

AurOS will never phone you, and nobody from AurOS will ever ask to connect to your computer, or ask for money, a card number or gift cards. Anyone who does is not from AurOS.
